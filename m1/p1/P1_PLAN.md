### S1 — Domain, storage and policy (30 minutes)

Create shared P1 types and typed Person actor; Organization SQLite DO owns organization, org memberships, workspaces, workspace memberships, invitations, policy revision, idempotency and append-only admin AuditRecords. Server-generated IDs encode organization routing for Workspaces; reject parent mismatch. Each mutation atomically checks actor/revision/last-owner, writes state, increments revision, records replay and audit in one local transaction. Denials record bounded decision fields without bodies/secrets. Use 24-hour replay records; seven-day exact-numeric-id invitations activate only on acceptance; creator explicitly accepts manager membership in workspace creation. Audit retention is 90 days with bounded cleanup (`m1/M1_ARCHITECTURE_PROPOSAL.md:26-36`, `:52`, `:169-175`).

IdentityDirectory `directory-v1` maps numeric GitHub ID ↔ Person UUID, routes invitations and owns directory-idempotent org creation. Organization outbox repairs derived Person→org index; listings recheck authoritative active membership before disclosing names. Stale candidates never authorize; missing entries may temporarily omit memberships, never open access (`m1/M1_ARCHITECTURE_PROPOSAL.md:36`).

Policy `decide` defaults deny on unknown actors/actions/resources, inactive memberships, mismatched IDs or unavailable authority. Role→P1-action table: owner/admin get organization.manage/member.manage and workspace.create/manage/member.manage, with owner-only transfer/deletion/ceiling restrictions; manager gets workspace.read/manage/member.manage within org ceiling; contributor/viewer get workspace.read; ordinary org member gets no workspace actions. Active org AND workspace membership is required for content; admin metadata/administration is a separately enumerated exception, never shared-content/private-session access. No non-P1 action becomes allowed (`m1/M1_ARCHITECTURE_PROPOSAL.md:72-86`).

Preserve CHANNEL/v1; add ORGANIZATION→Organization and IDENTITY_DIRECTORY→IdentityDirectory; append exactly `{ "tag":"v2-m1-authorization", "new_sqlite_classes":["Organization","IdentityDirectory"] }`; export classes, update Env and shared barrel (`m1/M1_ARCHITECTURE_PROPOSAL.md:34`; existing `worker/wrangler.jsonc:20-23`, `worker/worker-configuration.d.ts:23`, `shared/src/index.ts:29`). Add DO/policy tests. Exit: transaction rollback/replay, isolation, roles and index-repair cases pass targeted verification, or report actual blockers.

### S2 — Native authentication and API (30 minutes; depends S1)

Add numeric identity seam alongside existing `userLogin`, preserving FakeSignIn compatibility (`worker/src/github/app.ts:54`, `:245-249`; `worker/test/fake-github.ts:477-514`). Add a separate native fixture, not modifications to existing test helpers. Version native session payload with issuer/personId/githubId/login/expiry; validate all fields and directory association. Keep legacy HMAC/session readers and displayed login semantics compatible (`worker/src/session.ts:51-86`). Legacy login-only/agent/connector/Host credentials cannot enter `/api/m1`; no actor from request body. Login recycling cannot upgrade historical sessions.

Extend browser and device auth with explicit native destination, authenticated in OAuth state; only native entry bypasses repo membership, never legacy entry (`worker/src/auth-api.ts:128-192`, `:222-249`). Native browser writes require same-origin Origin/CSRF validation including missing-Origin rejection; bearer authentication is separate. Existing cookie code only rejects a present foreign Origin, so native resolution must not inherit that weaker behavior (`worker/src/auth.ts:88-114`).

Route `/api/m1` before repo dispatch (`worker/src/index.ts:372-404`). workspace-api implements P1 §12: organizations create/list/get/patch; org members list/invite/change/revoke; invitation accept; workspace create/list/get/patch; workspace members list/invite/grant/change/revoke; org audit read. Only active admin may read audit. Use typed resources, body validation, Idempotency-Key on writes, If-Match on PATCH, 409 on stale revision or changed-body replay, no-store everywhere, `{error:{code,reason},policyRevision,requestId}` and opaque foreign-ID denials. Bounded cursors are scope-bound and reauthorized each page (`m1/M1_ARCHITECTURE_PROPOSAL.md:173-190`, `:199`). No agent/grant/consent endpoints. Add HTTP cases to organizations tests and native-auth tests. Exit: native browser/device identity plus negative API matrix verified.

## 5. Risks, assumptions and escalations

- Thirty minutes per slice is an aggressive planning target; atomic cross-object recovery and adversarial coverage may require continuation. Never trade denial correctness for timing.
- General-user enablement has no deployment toggle specified; assume local-only foundation until P3, no new security-default environment switch (`m1/M1_ARCHITECTURE_PROPOSAL.md:34`, `:42`).
- Escalation for review: S3 closure guards exceed literal “binding schema only” ownership wording but are necessary to honor linked-data denial; keep them fail-closed and minimal, record exact implementation scope before review. If an uncovered entry point requires P3 work, keep binding activation denied and report it rather than open access.
- Cross-DO operations are not atomic: durable outbox/repair and pending-closed generations are mandatory. Directory/Organization failure never invokes legacy grace (`m1/M1_ARCHITECTURE_PROPOSAL.md:36-40`).
- Admin metadata exception must never become content authority. Invitation login resolution must use verified numeric GitHub identity; if no safe server lookup is available, accept verified numeric targets only and record the limitation (`m1/M1_ARCHITECTURE_PROPOSAL.md:52`).
- Do not change existing tests to accommodate regressions. Stop and record any necessary existing-test change or trust-boundary ambiguity under Escalations in the implementation notes. Tests/builds/lint/typecheck for this documentation task: **not run**.
