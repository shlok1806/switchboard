# P3 permit and Host-bound consent redesign

Status: proposed for independent agy review; no implementation authorized until GO. Scope: PCFIX only. This design preserves Channel, existing registration/claim/task algorithms, manager-only START and the unlinked path. Tests: not run.

## Evidence and root cause

- Managed registration creates an Organization execution before obtaining its START permit, initializes local tables, and on failure queues an end; it calls registration before consuming START (worker/src/channel.ts:2841, :2857, :2939, :2948). The internal routine consumes a resume ticket, joins a Person and awaits Agent registration before consuming HAND (worker/src/channel.ts:3128, :3141, :3147, :3149). Agent registration writes rows, events and broadcasts before its final watch await (worker/src/agents.ts:252, :310, :363, :374). Thus denial can follow visible effects, including changes to the previous association.
- Consent creation currently derives owner from the target execution and checks workspace.read, then explicitly denies terminal_control issuance (worker/src/organization.ts:883, :894, :901). It does not establish Host ownership. Control effects are also unconditionally denied (worker/src/organization.ts:1111). The approval descriptor and resource omit Host ID (worker/src/managed-channel.ts:176; worker/src/channel.ts:2275); policy requires an exact nonempty Host match (worker/src/policy.ts:246, :253). Moreover the permit resource serialization omits hostId entirely (worker/src/policy-permits.ts:35): adding it to the policy input alone does not bind a permit to a Host.
- Channel Host rows record `person,name` and advisory limits (worker/src/hosts.ts:28, :260, :266). Agent registration stores a Host derived from Person/name (worker/src/agents.ts:303). Neither is an Organization-verified native Person ownership assertion. CLI's own limits and allow-list are local (cli/src/host/supervisor.ts:170, :186; cli/src/host/check.ts:56, :72); the approval denial instead sends an Agent interrupt (worker/src/channel.ts:2289), with no demonstrated local ceiling check.
- The supplied manager log reports owner approval deny expected 200 but got 404 (worker/test/managed-agent-controls.test.ts:273, :278) and consent creation expected true but got false (worker/test/managed-consent-control.test.ts:355, :374). XFIX1 deliberately closed these paths, while the next two commits recorded the blocker without changing production code (f9e1378, eeb2e97, 87b8813). The failures are not proof that the safe design is wrong. The lifecycle test's arbitrary Host fixture (worker/test/managed-consent-control.test.ts:357) is insufficient proof: keep its success assertion, first enroll a verified Host and bind the target to it. The owner-deny test retains its 200 assertion and response assertions; its fixture must establish verified enrollment through owner handoff registration. Neither test expectation is wrong under the owner ruling.

## Registration: one synchronous local commit

Choose option (a), not distributed rollback. Complete authentication, Task synchronization, non-mutating preparation and validation first. Keep serialization and required Idempotency-Key (worker/src/channel.ts:2753, :2839); no generated fallback. Preserve self-continuation and existing predecessor, librarian, nickname, paused/resume and ownership rules. Preparation must not consume resume tickets, end prior associations, write local SQL, broadcast, append events or touch queues. Split the existing Agent register into a synchronous local apply and the existing asynchronous watch scheduling; share the same algorithm with legacy registration, whose branch and timing stay unchanged. Check all failure predicates before writing; defer broadcasts and watch scheduling until transaction success. Any exception rolls back SQL and discards buffered in-memory notifications, not just the permit rows.

1. Authenticate Person and finalized binding; validate predecessor and existing association without effects; do all external sync first. Resolve exact predecessor execution and binding generation. Recheck all mutable facts after every await, particularly after the last one.
2. Avoid the current eager credential creation: add an Organization prepare/reserve operation, idempotently scoped to actor, registration body and key, with no active execution or secret issuance and no Channel mutation. In one Organization transaction call `decide` for START and, when needed, HAND, issue both exact-resource, one-use permits with the same policy revision and deadline at most two seconds, and reserve a non-authorizing execution identity. A timeout returns bounded 503. The reservation is not a Channel effect, is non-usable, bounded/expiring and contains no credential; audit only its eventual activation or expiry under existing bounded policy. Do not issue a reusable credential before local success.
3. Immediately after the final await, synchronously reread binding state, operation, generation, repo/Workspace, prior association, predecessor identity and presence, Host and resume ticket, and all local registration predicates. In ONE `transactionSync`, install and validate both receipts as a set (actor, exact action/resource, request ID, generation, equal current revision floor, deadlines, unused); consume both or throw to roll back. Use a single sampled time; any expired, revoked, stale, reused, missing or mismatched receipt throws. Then synchronously join Person, register Agent, consume resume ticket, write presence/roster, association, handoff/queue and event rows and outcome outbox in the existing order. No await, socket send or external callback occurs in the transaction. Buffer post-commit notifications. Prior execution termination is a durable post-commit intent, never pre-authorization. A denied/aborted attempt leaves no Channel roster, presence, handoff, queue, storage, broadcast or audit changes, including no permit-install residue; compare snapshots in tests.
4. Commit an outbox record and a **pending**, non-authorizing association in that transaction. Do not expose a live Agent, roster/presence, handoff or queue effect to readers or broadcast them until activation succeeds; stage their existing algorithm's changes transactionally and hide them while pending. The outbox identifies the exact consumed START and HAND receipts, verified owner handoff, registration, Host and generation; it contains no credential. Organization validates the correlated reservation and commit proof, then atomically activates the execution and writes enrollment, idempotently keyed by registration. It must not accept an arbitrary Channel RPC as proof: authenticate the bound Channel and use an Organization-issued unforgeable, single-use reservation correlated to both permits and the verified owner handoff; require a Channel commit acknowledgement for that exact reservation. Only this activation path can write enrollment. A registration without the owner's verified handoff cannot enroll a Host. No cross-DO atomicity is claimed.
5. Activation state machine: `pending` → `active` on confirmed activation → publish staged effects once, with generation/revision fence; `pending` → `reconciling` on timeout or ambiguous reply; retry the same idempotency key and reservation with bounded exponential backoff for at most 30 seconds. A client retry with the same key attaches to the durable outcome; a different body conflicts. An ambiguous timeout is never treated as failure until Organization confirms cancellation or reports activation. At deadline request idempotent cancellation/fencing at Organization; if unavailable, remain `reconciling`, invisible and non-authorizing, and retry with bounded backoff until authoritative resolution. If activation won, finalize or revoke/end it before cleanup; if cancellation won or activation is definitively rejected, transition `failed` synchronously, discard staged handoff/queue effects, mark association inactive and Agent gone, clean pending handoff, append one end event if a start was exposed, and emit no duplicate notifications. Terminal `failed` retries return the recorded failure; `active` retries return the recorded non-secret outcome, never replay a credential. Until completion return bounded 503. A lost activation reply is resolved by outcome lookup; never infer failure and leave an active orphan. Audit records commit, activation or terminal cleanup once, without secrets.

The existing permit primitive expects consumption in the same local transaction as writes and audit (worker/src/policy-permits.ts:89). Revocation invalidation and the two-second deadline bound, rather than instantaneous cross-DO atomicity, remain those of ADR 0057. Fail closed if local transaction semantics or buffering cannot guarantee the above; do not send before commit. Unlinked operations take their existing synchronous binding branch before added work and retain the existing registration method.

## Trusted Host ownership and consent

PCFIX adds an Organization `host_enrollments` table with `(organizationId, workspaceId, hostId)` primary key, `ownerPersonId`, enrolling registration and execution references, `createdAt`, and nullable `revokedAt`. Bound rows per Organization/Workspace using the existing bounded identity policy; reject capacity exhaustion. No credentials, digests or new binding. The only writer is the activation of a registration whose owner's verified handoff and START/HAND receipts were consumed in the local transaction above. Organization validates the reservation, owner, execution and bound Channel before the atomic enrollment/activation; repeat is idempotent, conflicts fail closed. A legacy Host or `agent.host` alone never enrolls. Bind the enrollment reference to the target execution; revoke it on unlink/rebind or ownership invalidation. No owner reassignment from a supplied login or Host ID. This attests the owner's verified handoff, not native machine identity or a CLI local ceiling.

At issuance Organization resolves the active row and target execution association itself; `decide` remains the single decision point and evaluates the existing action with an exact consent-issuance operation/target/field constraint, including active Organization and Workspace membership and issuer equals enrolled Host owner. No ad-hoc check substitutes for `decide`. Other DD-1 kinds use the same decision boundary and their own exact owner/field/target rules; Host-local kinds require the matching enrollment. Never equate execution owner with Host owner implicitly.

Store issuer Host owner separately from target execution owner when they differ; lookup and policy must check both. Consent is scoped to Workspace, Host, target execution, grantee Person, kind, expiry and revocation state. Issuance/revocation and revision advance are atomic in Organization, idempotent and auditable without secrets; revocation invalidates permits and linked Channel eligibility under ADR 0057. Expiry is checked at issuance and every use. Existing rows without verified issuer/enrollment are unusable, including rows predating XFIX1; no grandfathering. Screen/history/read consent is a different kind, cannot match `terminal_control`, and Host-local reads require nonempty exact Host IDs. Workspace grants and admin roles alone never grant control.

## Approval and dispatch

`/approval` is an execution's own prompt report; `/approval/deny` is a control effect (worker/src/channel.ts:2250, :2266). Resolve the current Agent association and its `host` (or `history_host` where applicable) only as a lookup hint. Organization independently resolves the active enrollment and execution binding and requires the same organization, Workspace, Host and owner; a missing or mismatched row denies. Populate the descriptor's resource with target execution, target owner, Host ID and operation before both `decide` and permit acquisition. Append `resource.hostId ?? null` to `resourceKey` (worker/src/policy-permits.ts:33); serialize every field used for the exact decision. A Host owner acting on their own agent requires no cross-owner consent. Any other Person requires current `terminal_control` consent from that Host owner, matching Workspace, Host, target execution, target owner, grantee, kind, expiry and non-revocation; ordinary Workspace grants and admin roles do not bypass it. `decide` evaluates the existing action with operation constraints for both cases.

After the final await re-read association, Host hint, approval ID, binding/generation and revision, then validate and consume the exact permit and synchronously commit the approval mutation and dispatch intent. Check the current invalidation generation/revision immediately before `interruptTo`, without an intervening await; stale or delayed dispatch reacquires authority. Permit issuance verifies current consent and enrollment; revocation cancels outstanding permits and advances the local fence under ADR 0057. Preserve Lead/holder restrictions. PCFIX opens Channel/Organization authorization now; machine-local owner/allow-list and limits are rechecked by the CLI daemon at the B3b/B4 boundary, not implemented in PCFIX (cli/src/host/supervisor.ts:170, :186; cli/src/host/check.ts:56, :72). A read, screen or history consent never authorizes approval, keystrokes or terminal input.

## Status and failure contract

Unknown/missing/mismatched Host, owner, target, membership, scope, consent, enrollment or permit deny; no positive cache. Managed foreign IDs and nonmembers receive uniform 404 (m1/M1_ARCHITECTURE_PROPOSAL.md:128; m1/p3/P3_ROUTE_INVENTORY.md:28; worker/src/managed-channel.ts:118); authenticated native authorization may return 403 without disclosing a foreign resource (worker/src/workspace-api.ts:22). Preserve 400 for malformed/missing key, 409 for conflicting idempotency/revision or self-continuation (m1/M1_ARCHITECTURE_PROPOSAL.md:175; worker/src/channel.ts:2793), and bounded 503 for timeout/unavailable authority (m1/M1_ARCHITECTURE_PROPOSAL.md:38; worker/src/workspace-api.ts:345). SPEC requires default deny and managed-route checks but does not prescribe these status codes (m1/SPEC.md:90). Do not turn transport failure into 404. Never report success after a rejected permit.

## Review disposition

No disproportionate architectural problem. The narrow extension adds one bounded Organization enrollment table and a recoverable registration outbox; it retains the existing policy authority and local registration algorithm.
