# P3 permit and Host-bound consent redesign

Status: proposed for independent agy review; no implementation authorized until GO. Scope: PCFIX only. This design preserves Channel, existing registration/claim/task algorithms, manager-only START and the unlinked path. Tests: not run.

## Evidence and root cause

- Managed registration creates an Organization execution before obtaining its START permit, initializes local tables, and on failure queues an end; it calls registration before consuming START (worker/src/channel.ts:2841, :2857, :2939, :2948). The internal routine consumes a resume ticket, joins a Person and awaits Agent registration before consuming HAND (worker/src/channel.ts:3128, :3141, :3147, :3149). Agent registration writes rows, events and broadcasts before its final watch await (worker/src/agents.ts:252, :310, :363, :374). Thus denial can follow visible effects, including changes to the previous association.
- Consent creation currently derives owner from the target execution and checks workspace.read, then explicitly denies terminal_control issuance (worker/src/organization.ts:883, :894, :901). It does not establish Host ownership. Control effects are also unconditionally denied (worker/src/organization.ts:1111). The approval descriptor and resource omit Host ID (worker/src/managed-channel.ts:176; worker/src/channel.ts:2275); policy requires an exact nonempty Host match (worker/src/policy.ts:246, :253). Moreover the permit resource serialization omits hostId entirely (worker/src/policy-permits.ts:35): adding it to the policy input alone does not bind a permit to a Host.
- Channel Host rows record `person,name` and advisory limits (worker/src/hosts.ts:28, :260, :266). Agent registration stores a Host derived from Person/name (worker/src/agents.ts:303). Neither is an Organization-verified native Person ownership assertion. CLI's own limits and allow-list are local (cli/src/host/supervisor.ts:170, :186; cli/src/host/check.ts:56, :72); the approval denial instead sends an Agent interrupt (worker/src/channel.ts:2289), with no demonstrated local ceiling check.
- The supplied manager log reports owner approval deny expected 200 but got 404 (worker/test/managed-agent-controls.test.ts:273, :278) and consent creation expected true but got false (worker/test/managed-consent-control.test.ts:355, :374). XFIX1 deliberately closed these paths, while the next two commits recorded the blocker without changing production code (f9e1378, eeb2e97, 87b8813). The failures are not proof that the safe design is wrong. The lifecycle test's arbitrary Host fixture (worker/test/managed-consent-control.test.ts:357) is insufficient proof: keep its success assertion, first enroll a verified Host and bind the target to it. The owner-deny test retains its 200 assertion and response assertions; its fixture must establish verified enrollment through owner handoff registration. Neither test expectation is wrong under the owner ruling.

## Registration: prepared durable intent (R10–R15)

The owner selected prepared intent, replacing the former pre-activation staged write set. Choose synchronous atomic local commits, not distributed rollback. TXN-1 consumes BOTH START and verified-owner HAND permits and writes only the registration intent plus the necessary permit-consumption bookkeeping. TXN-2 runs registration only after Organization activation and a fresh policy check. This deliberately supersedes the old requirement to apply registration in the first commit. No shadow/versioned shared rows or notification journal is introduced.

### Why intent is necessary

At HEAD, `#registerAgentInternal` consumes a resume ticket, joins the Person, awaits roster registration, drains next-turn queues, hands off and completes spawn (worker/src/channel.ts:3131, :3141, :3147, :3152, :3157). `withNextTurn` drains lost Claims, Relay deliveries and Directives (worker/src/channel.ts:3315–3319). Presence invokes shared claim recovery (worker/src/channel.ts:656–657; worker/src/stale-claims.ts:73); spawn changes parent/spawn records, sends and resolves a waiter (worker/src/hosts.ts:553–567); append broadcasts and invokes Relay (worker/src/channel.ts:4805–4807). Hiding a pending Agent cannot hide these mutations. None may occur in TXN-1.

### Intent schema and bounds (new design, not existing code)

Managed-only lazy table `registration_intents`: immutable payload columns `intentId`, `organizationId`, `workspaceId`, `channelId`, `bindingGeneration`, `actorPersonId`, `actorGithubId`, `principalId`, `reservedExecutionId`, `agentId`, `hostId`, `ownerPersonId`, `predecessorExecutionId`, `predecessorAgentId`, `requestId` (required client Idempotency-Key), `reservationId`, `startPermitId`, `handoffPermitId`, `policyRevision`, `verifiedOwnerHandoff=true`, `createdAt`, `expiresAt`, and `request` (explicitly allowlisted registration inputs). Nullable predecessor fields represent initial registration; HAND still attests the owner's one-time verified registration handoff, not an invented predecessor. Keep session ID/AgentId construction unchanged.

`request` contains only cli, sessionId, resumed, cwd, nickname, librarian, continues, host, historyHost, spawn and bounded usage fields already accepted by registration; no arbitrary object spread. Never persist a credential, digest, redemption/one-time code, raw authentication body or permit bearer material in the intent. Reservation/permit IDs are non-authorizing correlation references; require authenticated bound-Channel RPC, never possession of an ID, for completion. Apply existing request validation plus 16 KiB total serialized intent limit, 256-byte IDs, 4 KiB cwd, 128-byte nickname, and validated bounded usage scalars; reject oversize before permits, never truncate identities.

Separate mutable outcome columns: `state`, `failureCode`, `appliedAt`, `completedAt`, `cancelRequestedAt`; the payload is never updated. Unique `(workspaceId,bindingGeneration,actorPersonId,requestId)`; same key plus identical canonical payload attaches, changed payload returns 409. One live intent per `(workspaceId,agentId)` AND `(workspaceId,hostId)`; competing keys get 409, never replace an intent. A Host-less registration may not enroll/control a Host and has only agent uniqueness. TTL is 30 seconds from TXN-1, capped by handoff/grant/credential expiry. Both permits must be valid at TXN-1 (maximum two seconds); their later expiry is not a second consumption or extension. TXN-2 needs fresh authority as below.

Cap intent/outcome rows by `MANAGED_RECORD_CAP` (capacity failure 503), prune terminal rows after 24 hours; expired/purged keys cannot resurrect reservations or reuse handoffs. Organization keeps correlated reservation terminality under its bounded identity lifecycle; absence is denial, never implicit activation. Expiry/cancel is idempotent. No constructor/schema work on unlinked paths.

### Protocol and synchronous boundaries

1. Keep the synchronous in-memory unlinked branch before all new work. Managed preparation authenticates finalized binding and owner handoff, validates registration/predecessor rules without mutation, completes Task synchronization and all external reads first. Do not consume resume tickets or end an existing association. Preserve manager-only START and existing ownership/librarian/Lead rules. Required key and serialization already exist (worker/src/channel.ts:2753, :2839).
2. Organization prepares a bounded non-authorizing reservation, not the current eager usable execution/credential (worker/src/channel.ts:2841). Through `decide` issue correlated exact-resource START and HAND permits with common revision/generation/deadline, at most two seconds. Include intent ID, request ID, target agent/execution/Host/owner in the expected binding. Failure/timeout returns bounded 503, with no Channel registration effect. No credential is returned or stored locally.
3. **TXN-1:** after the final await reread binding/generation, actor, predecessor, Host, existing association and local predicates. In ONE `transactionSync`, install, validate and consume BOTH receipts as a set against independently reconstructed bindings, and insert the immutable intent. Sample one time; expired, revoked, reused, missing, wrong actor/action/resource/Host/revision/generation or binding mismatch aborts the transaction and rolls back both receipts and intent. The existing primitive validates deadlines, actor, resource, request, generation and revision and marks used (worker/src/policy-permits.ts:89–113); extend with atomic set consumption, not sequential commits. **Only the intent and receipt bookkeeping change.** No Person join, Agent/association row, roster, presence, resume/handoff state, queue, Claim, Relay, Directive, Task, Event, usage, host.spawned, parent, waiter, broadcast, registration audit or host_enrollments row is touched. No prior execution is ended. Failed TXN-1 leaves even receipt installation unchanged. Intent preparation is not a session.start audit event.
4. Send the authenticated bound-Channel commit acknowledgement for this exact reservation/intent and BOTH consumed IDs. Organization verifies correlation and verified-owner handoff and activates the reserved execution idempotently. Activation alone grants no Channel association, credential or enrollment; all managed execution use must require completed registration, so an activated-but-unapplied identity is unusable. An arbitrary Channel-provided Host/owner or reservation ID is never proof. Activation rejection, unavailable authority or timeout closes this attempt; follow cancellation below, never optimistically apply.
5. After confirmed activation, obtain a NEW `decide` check for exact registration/handoff/Host resource, including current sponsor authority, execution/grant validity and membership. Obtain a fresh exact-resource apply permit with deadline at most two seconds. This does not refund/reuse START or HAND; its binding references their consumption by this intent. **TXN-2:** after the last await synchronously reread binding/generation, revision floor, live immutable intent, activation correlation and all existing registration predicates; verify both original IDs were consumed by THIS intent, not another registration; consume the fresh apply permit. Denial, expiry, cancel or mismatch aborts with no shared effect. Invoke the existing synchronous registration algorithm in its existing order, including resume, Person join, Agent registration, presence/claim recovery, next-turn drain, handoff, usage and spawn SQL; write association and `applied` outcome atomically. No await between final fence and local effects. A business failure/exception rolls back ALL SQL and restores transaction-local in-memory counters/caches. Never keep partial resume/queue deletion.
6. Separate callbacks by effect, not by blanket buffering: presence/claim recovery and append SQL remain synchronous INSIDE TXN-2; external sends, Relay scheduling, watch scheduling, host.spawned send and waiter resolution execute only after successful commit, in existing order with generation/revision fence. Capture these only in a request-local list, discarded on rollback, not a durable staged write set/journal. The wrapper must cover nested append/Host callbacks, including lastSeq rollback. After commit, use existing delivery/reconnect semantics; do not rerun registration to replay a lost notification. Existing SQL and claim/task algorithms stay unchanged; only their authorization/transaction boundary and asynchronous watch separation change (worker/src/agents.ts:252, :374).
7. **Enrollment is TXN-2 completion only, never activation/TXN-1.** TXN-2 records a durable local applied proof for the verified owner handoff. Its authenticated completion RPC makes Organization write the enrollment in its own synchronous completion transaction, correlated to the consumed receipts, intent, applied proof and active reservation. This is the Organization portion of the second-commit protocol: Channel and Organization transactions are NOT one cross-DO synchronous transaction. No await occurs within either local transaction. Only this registration-completion handler writes host_enrollments; no generic enrollment API. Until acknowledgement, enrollment/credentials are unavailable and outcome is `applied`, not completed. Retry completion idempotently from the proof; never run registration twice. A completion timeout after successful TXN-2 is distinct from activation/recheck failure: local authorized registration has committed, but Host control and execution credential release remain closed. Organization checks current generation and validity before enrollment; if invalid, end execution and retain a terminal applied outcome, never pretend to undo already committed shared work.
8. Return the completed non-secret registration outcome only after completion acknowledgement and response-time binding check; credential delivery uses existing Organization credential channel, never Channel storage. Prior association termination is authorized and scheduled only after successful TXN-2, not during preparation. Audits distinguish authority activation/cancel from local registration success; append registration audit once with TXN-2. A failed preparation/activation/recheck has no session/registration audit; Organization may audit its own reservation cancellation without exposing secrets.

### Live state wins (R13)

TXN-1 stores NO queue/Task snapshot. TXN-2 reads current resume/spawn/predecessor/Task state and drains exactly the live lost-Claim, Relay and Directive queues through the existing algorithm. Items delivered/acknowledged/cancelled/taken over between commits stay so; newly queued items are eligible under existing rules; no deleted row is restored and no old claim is resurrected. Presence recovery and handoff use the Task/ownership visible at TXN-2, not intent time. If changed state violates a registration prerequisite (resume consumed, predecessor changed, librarian conflict, spawn no longer eligible), preserve the existing predicate/result: required predicate failure cancels with no shared effect; optional spawn handling remains the existing no-op. Task synchronization completes before fresh apply-permit acquisition; reread again inside TXN-2. Concurrent operations serialize at the local transaction, not across the activation await.

### PC-4 state machine and visibility

| State | Transition / retry | Visible effects |
| --- | --- | --- |
| absent | valid dual-permit TXN-1 → prepared; failure stays absent | None |
| prepared | confirmed activation → activated; failure/timeout/denial/TTL/cancel → cancelling | Intent/consumption bookkeeping only; no shared registration state |
| activated | fresh check + valid TXN-2 → applied; any refusal/expiry/cancel → cancelling | No shared registration state before TXN-2; no enrollment/credential |
| cancelling | idempotently cancel reservation/end activated execution; authoritative confirmation → cancelled/expired/failed | Never apply; no shared registration effect, even if cancellation RPC is unavailable |
| applied | idempotent enrollment/completion acknowledgement → completed; invalidation → terminal applied-failed | TXN-2's authorized shared state; no Host control/credential until completion |
| completed | identical retry returns recorded non-secret outcome | Existing registered Agent; enrollment usable only while current |
| cancelled / expired / failed / applied-failed | terminal; same key returns recorded result, new attempt requires new verified handoff | Pre-apply terminal states have zero shared registration effect; applied-failed records committed registration and ends its managed authority |

A crash after TXN-1 recovers intent, never applies on a guessed activation result. A lost activation response is a timeout and closes apply eligibility; reconcile only to cancel/end, not resume apply. A crash after confirmed activation but before TXN-2 must redo the fresh authority check and fences before the immutable TTL, otherwise cancel. A crash after TXN-2 uses `applied` proof to finish enrollment or terminate authority, never repeats queues/Tasks/notifications. Serialized cancellation vs TXN-2 has one winner: cancel first forbids apply; committed apply first is an applied outcome, not a falsely reported no-effect cancellation. Organization cancellation is fenced against delayed activation; repeat activation cannot revive terminal reservations. Consumed permits are NEVER refunded. Same-key retries observe/attach, never start a new activation after timeout; new attempt requires a new handoff and permits. Keep cancelling tombstones bounded and non-authorizing while authority is down; return bounded 503, no indefinite request wait. No positive authorization cache: confirmed activation is lifecycle state, never a substitute for TXN-2 `decide`.

## Trusted Host ownership and consent

PCFIX adds an Organization `host_enrollments` table with `(organizationId, workspaceId, hostId)` primary key, `ownerPersonId`, enrolling registration and execution references, `createdAt`, and nullable `revokedAt`. Enforce `MANAGED_RECORD_CAP` before insert, including retained revoked rows; reject capacity exhaustion with 503 and prune revoked rows under bounded retention. Invalidate matching enrollment on execution end/revoke, unlink/rebind or ownership invalidation; policy/permit queries require `revokedAt IS NULL` and a current enrolling execution. Extend the existing execution lifecycle hooks (worker/src/organization.ts:525–527, :701–720). No credentials, digests or new binding. The only writer is the Organization TXN-2 registration-completion transaction described above, after verified owner handoff, consumption of BOTH permits and local apply proof. Activation alone writes no enrollment. Organization validates reservation, owner, execution, generation and bound Channel; repeat is idempotent, conflicts fail closed. A legacy Host or `agent.host` alone never enrolls. Bind the enrollment reference to the target execution; revoke it on unlink/rebind or ownership invalidation. No owner reassignment from a supplied login or Host ID. This attests the owner's verified handoff, not native machine identity or a CLI local ceiling.

At issuance Organization resolves the active row and target execution association itself; `decide` remains the single decision point and evaluates existing `workspace.read` with exact `operation=consent.issue`, consent kind, target execution, Host and field constraints (the current issuance uses workspace.read at worker/src/organization.ts:894; a general read allow must not authorize issuance), including active Organization and Workspace membership and issuer equals enrolled Host owner. No ad-hoc check substitutes for `decide`. Other DD-1 kinds use the same decision boundary and their own exact owner/field/target rules; Host-local kinds require the matching enrollment. Never equate execution owner with Host owner implicitly.

Store issuer Host owner separately from target execution owner when they differ; lookup and policy must check both. Consent is scoped to Workspace, Host, target execution, grantee Person, kind, expiry and revocation state. Issuance/revocation and revision advance are atomic in Organization, idempotent and auditable without secrets; revocation invalidates permits and linked Channel eligibility under ADR 0057. Expiry is checked at issuance and every use. Existing rows without verified issuer/enrollment are unusable, including rows predating XFIX1; no grandfathering. Screen/history/read consent is a different kind, cannot match `terminal_control`, and Host-local reads require nonempty exact Host IDs. Workspace grants and admin roles alone never grant control.

## Approval and dispatch

`/approval` is an execution's own prompt report; `/approval/deny` is a control effect (worker/src/channel.ts:2250, :2266). Resolve the current Agent association and its `host` (or `history_host` where applicable) only as a lookup hint. Organization independently resolves the active enrollment and execution binding and requires the same organization, Workspace, Host and owner; a missing or mismatched row denies. Populate the descriptor's OUTER enforcement input with `targetExecutionId` and resource target owner, Host ID and operation BEFORE `prepare()` as well as `decide`; a temporary copied input for a preliminary check is insufficient because prepare closes over the outer input (worker/src/channel.ts:1691–1706, :2275–2287; worker/src/managed-channel.ts:176). Append `resource.hostId ?? null` to `resourceKey` (worker/src/policy-permits.ts:33); serialize every field used for the exact decision. A Host owner acting on their own agent requires no cross-owner consent. Any other Person requires current `terminal_control` consent from that Host owner, matching Workspace, Host, target execution, target owner, grantee, kind, expiry and non-revocation; ordinary Workspace grants and admin roles do not bypass it. `decide` evaluates the existing action with operation constraints for both cases.

After the final await re-read association, Host hint, approval ID, binding/generation and revision, then validate and consume the exact permit and synchronously commit the approval mutation and dispatch intent. Check the current invalidation generation/revision immediately before `interruptTo`, without an intervening await; stale or delayed dispatch reacquires authority. Permit issuance verifies current consent and enrollment; revocation cancels outstanding permits and advances the local fence under ADR 0057. Preserve Lead/holder restrictions. PCFIX opens Channel/Organization authorization now; machine-local owner/allow-list and limits are rechecked by the CLI daemon at the B3b/B4 boundary, not implemented in PCFIX (cli/src/host/supervisor.ts:170, :186; cli/src/host/check.ts:56, :72). A read, screen or history consent never authorizes approval, keystrokes or terminal input.

## Status and failure contract

Unknown/missing/mismatched Host, owner, target, membership, scope, consent, enrollment or permit deny; no positive cache. Managed foreign IDs and nonmembers receive uniform 404 (m1/M1_ARCHITECTURE_PROPOSAL.md:128; m1/p3/P3_ROUTE_INVENTORY.md:28; worker/src/managed-channel.ts:118); authenticated native authorization may return 403 without disclosing a foreign resource (worker/src/workspace-api.ts:22). Preserve 400 for malformed/missing key, 409 for conflicting idempotency/revision or self-continuation (m1/M1_ARCHITECTURE_PROPOSAL.md:175; worker/src/channel.ts:2793), and bounded 503 for timeout/unavailable authority (m1/M1_ARCHITECTURE_PROPOSAL.md:38; worker/src/workspace-api.ts:345). SPEC requires default deny and managed-route checks but does not prescribe these status codes (m1/SPEC.md:90). Do not turn transport failure into 404. Never report success after a rejected permit.
