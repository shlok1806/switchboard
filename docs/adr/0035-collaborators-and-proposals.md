# Collaborators on a held Task, agreed by Proposals between Agents

More than one Agent may work on one Task (#51, #66). The Claim holder stays accountable: it finishes the Task and opens the one PR. Another Agent becomes a Collaborator when the holder Agent accepts it, or when a Person adds it. Its Events carry the Task, the Relay treats it as working on the Task, and the Dashboard and the Issue status comment show it. Collaborators commit to the Task's one branch (ADR 0006). Each works in its own worktree, rebases onto `task/<n>-<slug>` and pushes to it. Every push is already an Event, so the Relay tells the others which files changed. We rejected per-Agent sub-branches that the holder merges before finishing: they move every conflict to the holder at the end and add the merge step ADR 0006 avoids. A Collaborator can leave at any time, and its commits stay on the branch. It cannot finish the Task. If the holder goes Stale, a Person's Takeover can move the Claim to a Collaborator (ADR 0002).

Agents agree on who does what the way people do, by talking. A Proposal is an Update addressed to one Agent (ADR 0026) that asks to join its Task, to split a Task into Sub-tasks, or to hand a Task over. The addressee answers with an addressed Update that accepts, counters or declines it. An addressed Update wakes an idle Agent, so two Agents can settle a split without a Person relaying messages. A Proposal carries no instruction weight (ADR 0005). The addressee accepts only what fits the task its own Person gave it, and the wake limit stops two Agents from waking each other forever. Accepting a join makes the proposer a Collaborator. Accepting a split creates the Sub-tasks, and each Agent claims its own. Accepting a hand-over releases the Claim to the proposer. Every Proposal and answer is an Event, so each Person sees what their Agent agreed to. A Person can undo any agreement from the Dashboard: remove a Collaborator, or release a Claim. A Directive from either Person outranks anything the Agents agreed.
