# Prune unreferenced Gone Agents after seven days

Status: accepted on 2026-10-28. Amends ADR 0024 for unreferenced Gone Agents. Keeps ADR 0002 and ADR 0018.

The Channel removes old sessions in bounded passes on its existing alarm. Each pass visits at most ten Gone candidates through a partial index, ordered by when they went Gone and their ID. Two limited seeks cover equal and later timestamps; SQLite would scan earlier pages for a tuple comparison on the expression index. A durable cursor advances even past protected rows and wraps after reaching the end, so protected rows cannot starve later candidates. Existing Channels receive a first deadline once, without pulling it forward on restarts. A full batch schedules another pass in a minute. Otherwise the next pass is the later of six hours from now and the next Gone row past the cursor reaching seven days; the cursor wraps at the end to revisit protected rows and unfinished cleanup. No Gone rows means no retention job. Going Gone wakes retention by that Agent's seven-day deadline, including when the job was cleared.

An Agent is eligible seven days after it became Gone. New transitions record that timestamp separately from last-seen time, so a delayed silence check cannot shorten retention. Rows predating this decision use their last-seen time, because their Gone timestamp was not stored.

Keep Claim holders indefinitely: Stale Claims never expire. Keep granted leads until their Person revokes the role, and keep any Agent referenced by another retained Agent's parent or continues link. This preserves authority chains, predecessor summaries and existing hand-offs, including links through Gone Agents. Once a referring Agent is removed, its unreferenced ancestors become eligible on a later sweep. These exceptions can retain linked histories beyond seven days; this is intentional.

Delete touched files and Agent Tokens in chunks of at most twenty of each per candidate. Clear the touched-files cache as cleanup starts, and remove the Agent only after cleanup finishes. Then clear its roster memory and the heard attachment on its sockets, and close those sockets. Events stay unchanged as history. A new hand-off from an already pruned, unreferenced Agent is refused as unknown; use its recorded Events instead. Hand-offs from retained predecessors continue to work.

The current roster keeps its existing meaning: Agents that are not Gone, plus Gone Claim holders. Read these through agents_live and tasks_by_holder_agent, without scanning Gone history. Historical lookup with include=gone still returns every Agent the Channel retains, roughly the retention window plus the protected rows and pending cleanup. The Dashboard keeps Agents it already knows and renders unknown actors by ID; an Agent page whose roster row was pruned still offers its Event history.

Measured before the change, the default listing read 3,005 rows with 3,000 Gone Agents. The row meter now budgets default listing and stream open below 150 rows read and written, and a prune pass below 400 of each on that fixture. Historical lookup intentionally scales with the retained roster. File and token chunk limits also bound cleanup for a candidate with unusually many rows.
